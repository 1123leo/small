# Flappy Bird PPO：觀測表徵比較

本專案建立一套可配對比較的 Flappy Bird PPO 實驗架構，探討在訓練設定盡量相同時，不同**觀測表徵**對學習表現與運算成本的影響。

## 研究問題

在相同遊戲環境、獎勵設計、PPO 超參數、訓練步數與評估程序下，9D、36D 與 180D 三種觀測表徵的學習分數曲線及運算資源指標有何差異？

- **自變項：**觀測表徵（9D、36D、180D）。
- **主要結果：**固定評估回合的平均分數及其隨訓練步數的變化。
- **次要結果：**完成訓練所需時間、每秒環境步數、程序 RAM 與 GPU 記憶體使用量。
- **控制項：**環境、獎勵、PPO 超參數、平行環境數、訓練步數及評估種子。

## 三種觀測條件

| 訓練程式 | 維度 | 輸入定義 | 主要比較意義 |
|---|---:|---|---|
| `train_ppo_obs_9d.py` | 9 | 單幀人工狀態特徵 | 基準狀態觀測 |
| `train_ppo_obs_36d.py` | 36 | 同一組 9 維特徵連續四幀堆疊 | 加入短期時間資訊 |
| `train_ppo_obs_180d.py` | 180 | Flappy Bird 環境的 Lidar 觀測 | 不同感測表徵 |

9D 特徵由鳥的垂直位置與速度、目標水管位置及間隙、速度與距離交互特徵、上升狀態旗標等組成；36D 使用相同的 9 個特徵，但串接最近四幀。180D 則直接使用環境提供的 Lidar observation。

> **重要限制：**這不是只改變數值維度的純粹資訊量實驗。9D 與 36D 的差異主要包含時間資訊；180D 則改變了感測表徵。因此結果應解讀為「不同觀測表徵的比較」，不宜單獨歸因於維度或資訊量。若要分離這些因素，可在後續實驗中固定表徵種類，再比較不同 frame stack 長度或不同 Lidar 解析度。

## 共用訓練與評估規格

三支程式以同一份訓練邏輯為基礎，僅選擇不同觀測模式。預設規格如下：

- 環境：`FlappyBird-v0`；平行環境數：4。
- 預設訓練量：每個條件 1,000,000 個環境步數；可用 `--total-timesteps` 調整。
- PPO：`MlpPolicy`、兩層各 128 單元的 Tanh 網路、learning rate `3e-4`、`n_steps=2048`、batch size `256`、`n_epochs=10`、`gamma=0.99`、`gae_lambda=0.95`、`clip_range=0.2`。
- 共用獎勵：每步 `+0.05`、通過水管 `+20`、回合結束 `-15`（結束懲罰覆蓋該步其他獎勵）。
- 評估：每 100,000 步，以相同的 10 個固定評估種子進行測試；保存平均分數、標準差、中位數、最高分及平均回合步數。
- 隨機種子預設為 `42`；訓練摘要記錄實際步數、執行裝置、環境與套件版本。

## 執行方式

安裝 PyTorch、Gymnasium、`flappy-bird-gymnasium`、Stable-Baselines3 與 TensorBoard；若要記錄程序 RAM 峰值，另安裝 `psutil`。使用 GPU 時，請安裝與本機 CUDA 環境相容的 PyTorch 版本。

為避免輸出混淆，請對三個表徵使用相同的 seed；例如：

```bash
python train_ppo_obs_9d.py --seed 42 --total-timesteps 1000000
python train_ppo_obs_36d.py --seed 42 --total-timesteps 1000000
python train_ppo_obs_180d.py --seed 42 --total-timesteps 1000000
```

進一步比較訓練隨機性時，應使用多組配對 seed（例如 `42`、`43`、`44`），每個表徵都跑完整的同一組 seed。每次執行的輸出位於：

```text
models/standardized/obs_<mode>_seed_<seed>/
```

該目錄包含最終模型、定期 checkpoints、TensorBoard 記錄、逐次評估 CSV 與 `training_summary.json`。若該 seed 的輸出目錄已有內容，程式會停止而不覆寫或混合結果；請先封存舊資料，或選用新的 seed。

## 指標與公平比較

- **表現：**比較各檢查點的平均分數曲線；同時保留每次評估的分數分散程度。評估回合的標準差不等於不同訓練 seed 之間的不確定性，兩者應分開報告。
- **運算成本：**摘要記錄包含評估時間的總耗時、環境步數／秒、可選的週期取樣 RAM 峰值，以及 CUDA 可用時的 GPU 記憶體峰值。
- **公平性：**硬體比較應在同一台機器、相同軟體環境與相近背景負載下進行；報告硬體與套件版本。若比較多組 seed，建議交錯或隨機安排條件的執行順序，減少溫度及背景負載造成的順序偏差。

目前新增的標準化程式尚未在此工作區完成實際訓練；執行並檢查輸出前，不應將任何預期差異寫成研究結果。
